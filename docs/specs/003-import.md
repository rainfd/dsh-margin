# 003 URL / PDF 异步导入

**状态：受控 URL/PDF 导入与任务跟踪代码已实现；待 GUI/授权导入集成验收，默认关闭。**

## 前置条件

002 的独立写闸门与明确授权规则；核验当前 Margin 导入、上传及任务查询能力。采集、解析、URL 归一化和去重继续由 Margin 后端执行。

## 范围与非目标

- 用户明确提交 URL 或选择 PDF 后才导入；展示排队、处理中、成功、失败等经后端核验的状态。提交已受理不等于文章已完成。
- 若后端不提供百分比，仅显示阶段/等待时间，不制造进度数字。任务身份按实例隔离，轮询有退避、超时和上限，关闭面板停止本地轮询但不谎称取消后端任务。
- 失败区分可重试、需更换凭据、重复内容和不支持格式；重试先查询现有任务，避免重复提交。重复项展示既有 Margin 文章入口。
- URL 安全、SSRF、防重定向绕过由服务端承担；文件类型、大小和路径安全由 host 与后端双重限制，文件名不作为可信路径。上传临时文件按有界策略清理。
- 不迁移采集引擎，不本地解析 PDF，不复制 Python，不自动抓取会话里所有链接，不将正文或文件二进制塞入工具输出。

## API 核验需要

已静态核验本机 Margin 当前源码，非沿用 10 月 8 日记录：

- `POST /api/imports` JSON `{url}`；`POST /api/imports/pdf` multipart 单字段 `file`。两者成功均为 **202** `{id,status:'processing',title,source_url,source_type,message}`；id 是占位 candidate ID，不是单独任务 ID。PDF source_url 为 `local-pdf://…`，不能把它拿去 URL 重试。
- `GET /api/imports/queue?limit=20` 返回数组，最多最近 20 项，含 candidate id、processing/unprocessed/read/error、error_message 等元数据；没有分页、按 ID 查询或百分比。
- 已接受 ID 可用现有 candidate 详情复查状态，但其正文很大，插件只向浏览器保留任务元数据。404/500/缺席均不代表导入成功。
- 后端 PDF 默认上限为 20 MiB（可配置，现网值未核验），检查非空与 `%PDF-`；插件另加 10 MiB、文件名/类型限制及二次标识校验，不能宣称等于完整 PDF 安全解析。
- 重复 URL/PDF 返回通用 409，没有已有 candidate ID；不伪造重复项文章链接。没有幂等键、导入任务重试或取消 API。candidate 的 retry-content 不是 PDF 二进制重放，不能冒充导入任务重试。

真实实例只读核验：队列接口成功返回 20 项（19 项 unprocessed、1 项 read），只暴露元数据且未含配置 token。未执行真实 POST/上传，实际 URL/PDF 完整导入与后端版本一致性仍待授权验证。

## 验收与测试

- URL 正常、无效、私网/重定向、重复；PDF 正常、超限、伪造 MIME、解析失败均有可恢复提示。
- 提交超时但后端已受理、轮询断网、重复点击、面板重开与实例切换不产生误关联或重复文章。
- 重试仅在明确动作后触发；未开启写权限时直接请求也拒绝；成功后可打开正确详情且列表可刷新。
- 日志、工具结果和错误不含 Cookie/token/文件正文；后端未知状态显示未知而非成功。

## 实施记录与受控限制

验证：`npm run typecheck`、`npm run build`、`npm test`（138/138）、`git diff --check` 均通过。真实实例只读取队列，没有 POST/上传。

- 主写闸门 `allowWrites` 之外新增 `allowUrlImports`、`allowPdfImports`，两项默认 false；必须同时获得主闸门与该类型授权。默认仅可读队列。运行中配置未被打开。
- 新增 `/api/dsh-margin/imports`、`/import-task` GET，及 `/import-url` JSON POST、`/import-pdf` multipart POST。全部沿用 DSH 会话/来源校验；写入在读取请求体前后复查实时权限，并绑定提交时的实例地址。
- PDF 全程有界内存二进制转发，不接收客户端本地路径、不写临时文件；最多 10 MiB，整个 multipart 上限另加 64 KiB；读取过程和 Content-Length 均限制，解析前限制部件数，只允许 file+instanceUrl。上游重新构造只含 file 的 multipart，由运行时生成 boundary。
- URL host 拒绝危险 scheme、凭据、空白控制字符及常见私网/localhost 字面量；IPv6 字面量保守拒绝。此检查不是 DNS/重定向 SSRF 防护，后者继续由 Margin 实现，插件不直接抓用户 URL。
- 页面区分“已接受”与“已就绪”，没有伪造百分比；显式表单提交同步加锁。轮询退避且有 20 次/10 分钟上限，关闭/切实例/卸载使迟到结果失效；最多跟踪 3 项已接受任务，并用只读详情复查不在最近队列的项目。
- 提交超时或断网时不自动重发；同次提交指纹受阻，成功的显式只读检查后才能再次由用户动作提交。没有重试任务/取消按钮；关闭界面不声称取消后台工作。
- 阅读列表和文章在导入面板后保持挂载；已完成项读取并复核实例后才能进入阅读器。并发打开的旧响应不得替换后来选择的文章。
- 本地假 Margin 覆盖真实二进制 multipart、限流/超限/多文件/类型/标识、默认拒绝、实时撤权、实例错配、202/409/畸形回执、慢响应体超时和 GET-only 复查；UI 为可控会话/事件测试，不替代真实 DOM/浏览器。

### 已确认的后端限制（不在插件中伪装修复）

PDF worker 会在处理中删除占位 FeedEntry，而队列使用 inner join；部分处理中/失败 PDF 因此可能消失，candidate 详情也可能暂时或持续不可读。插件保留已接受 ID并显示 **未知/需核实**，不判成功、不自动重建任务。后端尚无可靠的 PDF 重放/取消；因此 PDF 必须保持独立灰度开关，完整进度可靠性与失败恢复验收未完成。URL/PDF 任务不是持久可重放队列；停服务、自动恢复等运维能力未迁移。

GUI、真实导入、加密/损坏 PDF、重定向 SSRF 的授权集成测试及后端上述缺陷处理仍待完成。没有修改 Margin 后端，也没有在生产导入文章/文件。

## 本轮补强（2026-10-26）

- 导入队列/任务 GET 与两类 POST 统一加 20 秒 `AbortController` 上限：挂起的请求不会让 `checking` 永久为真，轮询仍会安排下一次尝试，且不会因超时自动重提。
- `importError` 增加 401 分类（需更换凭据）和 `AbortError` 超时文案。

## 发布与回退

先 URL，后 PDF，每一类单独开关；在授权测试源验证后启用。关闭导入入口可回退 Margin Web，不停止队列、不删除已导入文章；在途任务继续由原后端管理。
