## 不变的架构边界

- Margin 后端继续作为文章、采集加工、来源、阅读状态及既有高亮/笔记的唯一真源；DSH 接管阅读交互、编排和按需 AI。保留后端，不复制全部存储，不重写 Python 服务。
- Trilium 保存知识与任务账本；普通文章不等于任务。DSH 缓存仅为可丢弃副本，阅读进度只能增加观测维度，不能另建已读状态真源。
- 默认只读；读文章不自动标已读、不保存 Trilium、不导入、不创建批注。写入需对应能力开关与用户明确动作。
- 默认不停止 Margin 后端、RSS 调度或旧 Web；保留旧阅读入口作为降级路径。

## 证据与 API 纪律

参考历史设计：[功能拆分与归位](../功能拆分与归位.md)、[以阅读为基准](../功能整理-以阅读为基准.md)，均日期为 2026-10-08，**不是当前线上验证**；其中数量、延迟、服务/PID、已装 bundle、端点支持和安全判断必须重新核验。

本轮已核验并实现的后端事实覆盖 001–008（详见各规格「实施记录」）。本轮静态阅读的本地代码包括：[protocol](../../src/protocol.ts)、[Margin 客户端](../../src/margin.ts)、[路由](../../src/routes.ts)、[工具](../../src/tools.ts)、[列表](../../src/client/ReadingList.tsx)、[客户端入口](../../src/client/index.ts)、[配置存储](../../src/store.ts)。当前 `/api/dsh-margin` 已注册 29 条精确路由（配置、列表/详情、状态、导入、来源/凭据、AI、保存、注解、本地进度）。真实实例上只读核验过：列表有界扫描、详情正文、导入队列元数据、来源/凭据/调度元数据；**写入路径（阅读状态、导入、来源、凭据、保存、注解）只在本地假 Margin 集成测试中验证，未修改生产文章、未创建 Trilium 笔记、未上传真实 PDF**。AI 未对真实模型发起调用。

未支持或未核验的后端能力统一记为 **TBD**，不得从历史文档推导请求路径、方法、字段或完成状态。实施前记录目标实例/版本、能力、脱敏请求响应样本、失败分类、权限与测试时间；写操作只在获授权的测试对象上核验。不能支持时保留旧 Web 入口，不伪造本地成功。

## 共用发布与回退门槛

每份规格列出范围、非目标、API 核验、验收及回退。先 mock/契约测试，再授权集成测试和现有 DSH GUI 实测；测试结果未获得前不得把状态改为完成。构建/加载/刷新方式按当前 DSH 实际运行方式核验，不默认承诺热更新。关闭插件新入口即应能回到旧 Margin Web；回退不得删除真源数据、改写状态或停后端。当前已新增规格并实现 001–008 切片；构建产物在本仓库生成，尚未部署或宣称现有 GUI 已加载新版本。
