# Margin → DSH 功能拆分与归位

**日期：** 2026-10-08
**状态：** 拆分完成，归位方案待拍板
**依据：** Margin `999e3e0`（65,168 行：后端 41,429 Python + 前端 23,739 TS）实机核查；
DSH `packages/` 源码与生成目录（slot-catalog / api-catalog）；dsh-margin `cbd298b` 只读探针实跑。

---

## 0. 拆分方法：三个轴

单看「哪些功能能搬」会得出错误结论。每一项都要同时过三个轴：

| 轴 | 问题 | 决定的归属 |
|---|---|---|
| **轴 1 运行位置** | 需要服务端密钥 / 浏览器 DOM / 长驻进程吗？ | Client 插件 vs Host 插件 vs 留在 Margin |
| **轴 2 数据所有权** | 谁是唯一真源？ | 谁持有写权限 |
| **轴 3 已有对应物** | DSH 系统里是否已存在同职能服务？ | 新建 vs 复用 vs **合并冲突** |

轴 3 是这次拆分最重要的收获：Margin 有大量功能**不是不能搬，而是 DSH 里已经有更好的了**——
搬过来等于制造第二个真源。

## 3. 冲突与重复（本次拆分最重要的部分）

### 3.1 Trilium 写入双写 —— 最高风险

```
Margin  trilium_service.py (1,120 行)  ─┐
                                        ├─→  同一个 Trilium 实例
dsh-trilium (15+ 工具)                 ─┘
```

两侧都在写 Trilium，但**语义不同**：

| | 写什么 | 标签 |
|---|---|---|
| Margin | 文章笔记 | `category` / `savedDate` / `publishedDate` |
| dsh-trilium | **任务**笔记 | `task` / `taskStatus` / `marginCandidateId` / `sourceUrl` |

`reconciliation-rules.md:5` 明确警告：**不得把 Margin 保存的普通文章笔记当成任务**。
即两侧已意识到重叠并做了约定，但**约定是纸面的，没有代码强制**。

**建议：** 保留分工，但把「文章笔记 vs 任务笔记」的判据固化为 dsh-trilium 侧的校验，
并让 E2 建任务时复用 Margin 已保存的 `external_ref`，避免同一文章在 Trilium 出现两份。

### 3.2 AI 栈双份

Margin `codex`（本地子进程，`ai_model: gpt-5.6-luna`）vs DSH `ctx.llm`（profile 已配 workbuddy-cn + deepseek-v4.1-flash）。
**DSH 侧的 AI 问答应直接用 `ctx.llm`，不代理到 Margin**——省掉一条对本地 codex CLI 的进程依赖。

### 3.3 调度双份

Margin APScheduler（534 行，在跑）vs DSH `ctx.schedule`（`schedule_create` 等 4 个工具，**profile 未启用**）。
短期不合并；中期把「对账 reconcile」这类**跨系统**任务放 DSH，RSS 轮询留 Margin。

### 3.4 最高耦合点：高亮 offset 与渲染管线

这是**决定 reader 能做到哪一步**的技术事实：

1. 服务端按 `len(content_text)` 校验 `end_offset`（`highlights_router.py:53-93`）；
2. 客户端 offset 由**可见文本 TreeWalker** 截取（`textSelection.ts:52`，跳过删除按钮）；
3. 指纹在**浏览器**算（`crypto.subtle`，非安全上下文退化为 djb2）；
4. 存在**顺序不变量**：KaTeX 必须在算 offset 之前完成（`EditorialReader.tsx:163-170` 注释明示）；
5. `<mark>` 回填必须用**同一个** TreeWalker（`highlightRenderer.ts:40`）。

**结论：DSH 若以不同方式渲染正文，高亮必然漂移。** 三条出路：

| 方案 | 代价 | 建议 |
|---|---|---|
| ① DSH reader 放弃高亮，保留「在 Margin 打开」 | 零 | **阶段 B 采用** |
| ② 逐字节复刻渲染管线（含 KaTeX 顺序） | 高，且以后容易再次漂移 | 不推荐 |
| ③ 改 Margin 的 offset 模型为渲染无关（存上下文锚点） | 需改 Margin + 数据迁移 | **阶段 C 前提** |

### 3.5 「周报」概念冲突

Margin `digest`（文章摘要）与 dsh-trilium `trilium_weekly_report`（工作总结）不是一回事，
但都叫「周报」。**建议在命名与 UI 上明确区分**，避免 agent 走错系统。

### 3.6 双壳

Margin 有自己的登录页、导航、设置页、主题；DSH 有 Web GUI。
**在 DSH 内阅读时不应出现第二个导航壳。** 插件已正确使用 `--dsw-*` token，方向是对的。

## 5. 归位动作（按依赖排序）

### 阶段 A —— 修缺陷（无新增功能，先让现有部分不再骗人）

1. **设置卡 key**：`'dsh-margin-config'` → `'dsh-margin'`
   （`PluginManagerPage.tsx:612` 按 `pkg.name` 分发；对照 dsh-trilium 用 `'dsh-trilium'`）
2. **来源筛选失效**：后端无 `source_type` 参数，改为客户端过滤
3. **搜索 total 错误**：客户端过滤后重算 total
4. **详情丢正文**：`toCandidate` 补 `content_html`/`content_text`/`content_md`/`content_fetch_failed`
5. 重启 GUI（PID 23166 自 10-06 未重启，工具清单陈旧）

### 阶段 B —— 在 DSH 内真正「读」

6. 阅读器主面板（列表 → 正文两页，用 `children` 自声明子 slot）

8. 开写闸门：`margin_mark_read` + `margin_import_url`

### 阶段 C —— 打通回路 + 知识沉淀

11. AI 问答面板（`ctx.llm` + SSE）

13. **高亮/笔记**：前置条件是 §3.4 方案③
